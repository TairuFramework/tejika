# tejika local databases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** tejika resolves and opens local hozon databases: `getDatabasePath` in `@tejika/env` and a new Node-only `@tejika/db` with `openLocalDatabase`.

**Architecture:** `getDatabasePath` follows the existing `@tejika/env` path helpers (an `<APP>_…` override, else a file under `getDataDir`). `@tejika/db` is a thin opener: resolve the path, create the parent directory, build a `NodeSQLiteAdapter`, construct `HozonDB`, register stores, call `migrate()` eagerly, and close then rethrow on failure. No store code lives in tejika.

**Tech Stack:** TypeScript (NodeNext), `@hozon/db` ^0.1.0, `@hozon/node-sqlite` ^0.1.0 (node:sqlite), vitest, pnpm built-in versioning.

**Spec:** `/Users/paul/dev/yulsi/kigu/docs/superpowers/specs/2026-10-06-hozon-design.md` — §5 "Consumers › tejika", §1 "Stack placement", "Implementation order" step 2.

## Global Constraints

- `getDatabasePath(app, name = app)` → `<APP>_DATABASE_PATH` if set, else `join(getDataDir(app), `${name}.db`)`.
- `@tejika/db` is Node only; deps exactly `@tejika/env`, `@hozon/db`, `@hozon/node-sqlite`.
- `openLocalDatabase(params: { app: string; name?: string; path?: string; stores: Array<StoreDefinition<unknown, unknown>>; tablePrefix?: string; logger?: Logger; pragmas?: SQLitePragmas }): Promise<HozonDB>`.
- Resolves the path, creates the parent directory (not for `:memory:`), creates the adapter, registers stores, calls `db.migrate()` eagerly so version and migration errors surface at open; closes the handle and rethrows on failure.
- Approving the spec is the user sign-off tejika's `AGENTS.md` requires for the new package.
- Stack placement: `sozai ← hozon ← tejika ← mokei`; tejika depends on hozon through `@tejika/db` only.
- tejika conventions: `type` not `interface`, `Array<T>`, no `any`, ES `#private`, uppercase abbreviations (`ID`, `SQL`), pnpm only, never edit `lib/`.
- Cross-repo deps are `^` ranges in the catalog (`catalogMode: manual`); internal deps are `workspace:^`.
- Engines `node >=24`; CI runs ubuntu / macOS / windows × Node 24 / 26.
- Version bumps are patch (user ruling), including `@tejika/env`'s new export.
- Work on tejika branch `feat/hozon` (exists; user-created). Never commit to `main`.
- Publishing is outward-facing: ask the user before `pnpm run release`.

## Review Focus

1. Store definitions with concrete table and API types (`logStoreDefinition`, `telemetryStoreDefinition`) must be accepted by `stores` without casts — `StoreDefinition<unknown, unknown>` may reject them under `strictFunctionTypes`. Pinned by the type test in Task 2 Step 1.
2. A failed open on Windows must release the file (the handle is closed), so the caller can delete or reopen it. Pinned by Task 2's `releases the file after a failed migration`.
3. An explicit `path` or `<APP>_DATABASE_PATH` whose parent directory does not exist yet opens (directory created, recursively). Pinned by Task 2's `creates missing parent directories for an explicit path`.
4. `name` containing a path separator or `..` must throw like `getSocketPath`, rather than escaping the data dir. Pinned by Task 1's `rejects a name with a path separator`.
5. A database written by a newer schema (more migrations than registered) rejects at open with `SchemaVersionError`, not on first store use. Pinned by Task 2's `surfaces SchemaVersionError at open`.

```ts
const notes = (migrations: Array<string>) => ({
  name: 'notes',
  migrations: Object.fromEntries(migrations.map((id) => [id, { up: async (db) => {
    await db.schema.createTable(`notes_${id}`).ifNotExists().addColumn('id', 'integer').execute()
  } }])),
  createAPI: (db) => ({ count: async () => (await db.selectFrom('sqlite_master').selectAll().execute()).length }),
})
```

Tests (names exact):
- `opens <name>.db under the data dir and migrates eagerly` — `openLocalDatabase({ app: 'tejika-test', name: 'flow', stores: [notes(['001'])] })`; file `join(dataDir, 'flow.db')` exists; a sqlite_master query (via a fresh `NodeSQLiteAdapter` on the file after close, or the store API) shows table `notes_001` and `hozon_notes_migration` without any `getStore` call before close.
- `creates missing parent directories for an explicit path` — `path: join(dataDir, 'a', 'b', 'x.db')` opens and the file exists.
- `explicit path wins over <APP>_DATABASE_PATH` — set `TEJIKA_TEST_DATABASE_PATH` to one file, pass `path` to another; only `path` exists.
- `opens :memory: without touching the filesystem` — `path: ':memory:'`; resolves; `readdirSync(dataDir)` is empty and no `:memory:` entry appears in `process.cwd()`.
- `applies tablePrefix` — `tablePrefix: 'tj'`; `tj_notes_migration` exists, `hozon_notes_migration` does not.
- `rejects and releases the file after a failed migration` — a store whose migration `up` throws `new Error('boom')`; `openLocalDatabase` rejects with `'boom'`; then `rmSync(file)` succeeds (proves the handle closed — Windows refuses to delete an open file) and a later open of the same path with `notes(['001'])` resolves.
- `surfaces SchemaVersionError at open` — open with `notes(['001', '002'])`, close; open again with `notes(['001'])`; rejects with `SchemaVersionError` (import from `@hozon/db`).

- [ ] **Step 3: Implement `openLocalDatabase` in `packages/db/src/open.ts`**

`const path = params.path ?? getDatabasePath(params.app, params.name)`. Unless `path === ':memory:'`, `await mkdir(dirname(path), { recursive: true })`. Register each store with `db.register(store)`, then `await db.migrate()`, return `db`.
